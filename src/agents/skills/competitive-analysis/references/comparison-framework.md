# Competitive Analysis Comparison Framework

Use this framework to calibrate dimension-by-dimension competitor comparisons.

## Rating scale

- `Stronger`: evidence shows our position is advantaged on this dimension.
- `Comparable`: evidence shows no material gap or only minor trade-offs.
- `Weaker`: evidence shows the competitor has a meaningful advantage.
- `Unknown`: evidence is missing, stale, or contradictory.

## Core dimensions

### Feature Coverage
- Assess core overlap, missing capabilities, and depth vs surface parity.
- Prefer battlecards, product documentation, and transcript feature requests.
- Do not assume parity without evidence.

### Product Maturity
- Assess stability, enterprise readiness, security/compliance signals, and customer scale.
- Prefer proof signals over marketing language.

### Pricing Model
- Assess pricing structure, packaging, discount behavior, and commercial flexibility.
- If no pricing evidence exists, mark `Unknown`.

### Implementation Complexity
- Assess deployment time, integration burden, and services dependency.
- If implementation effort was not discussed, do not infer it.

### Time to Value
- Assess speed to first measurable outcome and onboarding friction.
- Prefer transcript evidence or documented proof over generic claims.

### Market Positioning
- Assess enterprise vs SMB focus, platform vs point solution, and stability vs innovation
  narrative.
- Do not restate vendor website copy.

### Proof / Customer Validation
- Assess named customers, relevant case studies, and industry credibility.
- If the buyer cites peer validation, prioritize that evidence.

### Support Model
- Assess SLAs, dedicated CSM coverage, and enterprise support posture.
- Mark `Unknown` if support evidence is not documented.

### Switching Cost
- Assess migration effort, contract lock-in, and integration entrenchment.
- Only describe switching cost as high/medium/low in narrative if evidence supports it.

## Tie-break rules

- Prefer direct, recent deal evidence over older general knowledge.
- Prefer first-party internal artifacts over unsupported external commentary.
- If two credible sources conflict and no recency tie-break exists, mark `Unknown`.
